# 研究生工位管理系统

固定二维码贴在工位桌上，学生扫码查看归属并提交申请；一工位一归属，二维码永不变化。

## 一、架构

```
┌─────────────── 微信小程序端 ───────────────┐
│ pages/register  扫码落地页（查看 / 申请 / 登记）   │
│ pages/home      首页（我的工位、扫码入口、公告）    │
│ pages/seat      工位地图（学生仅查看，登记需扫码）   │
│ pages/admin/*   后台：归属、办公室、学生、设置、二维码 │
│ pages/approval  审批（含一键通过） pages/records 记录 │
└───────────────┬───────────────────────────┘
                │ utils/api.js（统一接口层，USE_MOCK 切换本地/服务端）
┌───────────────▼───────────────────────────┐
│ server/index.js（Node 零依赖）数据文件 data/state.json │
└────────────────────────────────────────────┘
```

## 二、二维码不可变机制（一工位一码）

每个工位有三套编号，职责分离：

| 字段 | 含义 | 示例 | 是否可变 |
| --- | --- | --- | --- |
| `no` | **数字编号**，工位地图格子与详情大号显示 | `0102` | 随工位编号同步（改编号时自动取新编号中的数字部分） |
| `code` | **工位编号**，展示与检索用 | `A-0102` | 管理员可改（校验重名/空值） |
| `id` | **二维码编号**，生成后永久绑定该工位，二维码内容 `{QR_BASE}/s/{id}` | `S0001` | 永不变 |

- 工位的二维码只绑定 `id`：`https://seat.example.edu.cn/s/S0001`；改办公室名称、编号前缀、工位编号、行列数都不会影响已贴出的二维码。
- 修改工位编号时，数字编号 `no` 自动从新编号中提取数字部分（`A-8808` → `8808`；无数字则保留原值），地图显示同步更新。
- 旧数据缺少 `no` 时，`store.getSeats()` / 服务端 `seatView()` 会按行号列号自动补齐并落盘。
- 减少办公室行列数（或自定义布局的点位数）时，仅从末尾删除空闲工位（已登记工位拒绝删除）；删除办公室会连同空闲工位删除（二维码随之作废）。

### 自定义布局（工位地图）

办公室有两种布局方式，可在「办公室配置」里随时切换：

| 方式 | 说明 |
| --- | --- |
| 标准网格 | 原有逻辑：工位数 = 行数 × 列数，学生端按行列渲染成格子 |
| 自定义地图 | 上传办公室照片 / 平面图，在照片上**点击放置每个工位**，学生端按照片显示 |

自定义布局的操作路径（参照示例交互）：

1. 办公室配置 → 布局方式选「自定义地图」（新建时选了会直接进入编辑器）；
2. `/pages/admin/map` 编辑器：右侧「背景图」→ **拍照上传**（调用相机）/ **从相册选择**；照片会先压缩（quality 70）再 `POST /api/upload` 保存到服务端，返回 `/uploads/xxx.png` 的 URL（即「云端」），任何设备打开都能看到；服务端不可用时自动回退本机保存（`wx.env.USER_DATA_PATH`），功能不受影响。开关：`utils/config.js` 的 `UPLOAD_CLOUD`；
3. **点击画布空白处添加工位**；按住工位按钮**拖动**调整位置；点击工位可选中并删除；
4. 右侧「批量操作」可一次按 5 列铺开添加 N 个工位，或清空所有工位；
5. 「保存布局」→ 按点位顺序生成工位编号（`D-01`、`D-02`…）与二维码。

#### 地图照片与点位以服务端为准（`MAP_ON_SERVER`）

`utils/config.js` 的 `MAP_ON_SERVER: true` 时，**地图 photo + 点位一律读写服务端**，本机只作离线兜底：

| 环节 | 走向 | 说明 |
| --- | --- | --- |
| 上传照片 | 小程序 → `POST /api/upload` → 服务端 | 压缩（quality 70）后 base64 提交，服务端返回 `/uploads/xxx.png` |
| **保存布局** | `POST /api/admin/offices/:id/map`（image + points） | 成功后顺手写一份本机缓存；失败则只存本机并返回 `source: 'local'` 如实提示 |
| **打开 / 编辑地图** | `GET /api/admin/offices/:id/map` | 返回 office、image、points（含 seatId / code / no / status / owner） |
| **查看地图**（`pages/seat`） | 同上 GET | 先用本机缓存立即渲染，再用服务端结果整体替换（本机是网格也会切成地图视图） |
| 渲染照片 | `wx.downloadFile` 下载到本地缓存 | 避免 `<image>` 直连 http 被合法域名 / 证书校验挡住；下载失败退回远程地址 |

- **落库只存相对路径** `/uploads/xxx.png`：绝对地址里的 `127.0.0.1` 换台电脑/手机就失效；客户端渲染前统一用 `api.absImage()` 拼上当前 `BASE_URL`。
- 编辑器（`/pages/admin/map`）顶部显示数据来源标签：**已连接服务端 / 本机缓存**，并提供「重新拉取」放弃本机改动重拉服务端数据。
- 保存前若发现照片在本机（当时服务端不可用），会**先补传再保存**，杜绝「点位在服务端、照片只在本机」。
- 点位回传带上 `seatId`，服务端沿用同一批工位，编号与二维码不会变。
- 服务端不可用时（未启动 / 域名未配）不会白屏：读走本机缓存、写回本机并提示「已只保存在本机」，页面标签显示「本机缓存」。

关键约定：

- 点位坐标以**百分比**存储（`office.mapPoints: [{ seatId, x, y }]`），换屏幕、换设备都不会错位；
- 保存时按点位数量对齐工位：已登记工位按**顺序保留**（`id` 与二维码不变），多余的空闲工位才会被删除；
- 切回标准网格前会预检：若已登记工位超出 `行数 × 列数`，先提示释放或调大行列，不会改一半；
- 学生端 `pages/seat` 对自定义办公室渲染「照片 + 彩色工位按钮」，颜色沿用空闲/已占用/我的/维修中四种状态；点击后的详情与管理操作与网格布局完全一致；
- 照片走「服务端保存 = 云端」：`server/index.js` 提供 `POST /api/upload`（零依赖，base64 提交，PNG/JPEG/WEBP 文件头校验，上限 8MB）与 `GET /uploads/:name`（静态读取，禁止路径穿越）；文件落在 `server/data/uploads/`。
- 小程序端若要真机预览，需把 `utils/config.js` 的 `BASE_URL` 换成局域网/公网地址并在小程序后台配置 request 合法域名（开发者工具可勾选「不校验合法域名」）。
- 微信公众平台配置「扫普通链接二维码打开小程序」，跳转 `pages/register/register`，页面用 `util.parseSeatCode()` 解析 `q` 参数（支持 `/s/CODE`、`?code=`、`S0001`、`A-0102`）。

## 三、扫码与申请整合

**工位地图（`pages/seat`）对学生为纯查看页**：点击工位只能查看详情，不可申请/登记，登记与申请一律通过扫描工位二维码进入 `pages/register/register`（管理员在地图上的管理操作不受影响）。

| 工位状态 | 学生可用操作 |
| --- | --- |
| 空闲（审批模式） | 填写理由提交申请，使用期限由管理员设置，仅展示不可填报 |
| 空闲（直接登记模式） | 扫码即登记归属 |
| 本人已登记 | 查看归属与期限，可退订 |
| 他人已登记 | 仅展示（归属人脱敏），不可申请 |
| 停用维修 | 不可申请 |
| **已登记其他工位** | **在学生端直接驳回**：提示「你已登记工位 X，请先退订后再申请」，申请/登记按钮置灰，不再提供「退订并登记」的快捷通道；需先在原工位退订 |
| 不在登记开放时间内 | 提示具体开放/结束时间，不可申请 |

管理员在同一页面可释放归属、停用/恢复、复制二维码内容；审批通过后系统按管理员设置的期限写入归属。

## 四、管理员后台

| 页面 | 能力 |
| --- | --- |
| `pages/admin/seats` | 归属概览、按办公室/状态/关键字筛选、释放归属、停用/恢复、修改展示编号、查看二维码内容、退出登录 |
| `pages/admin/offices` | 设置办公室数量、每个办公室的**布局方式**（标准网格 / 自定义地图）、编号前缀、名称/楼栋；保存后自动补建或删除末尾空闲工位 |
| `pages/admin/map` | **工位地图编辑器**（自定义布局）：上传办公室照片、点击画布放置工位、拖动微调、批量添加、保存后自动生成工位编号与二维码 |
| `pages/admin/students` | 学生增删改查、多选批量删除；**上传 Excel 文件批量导入**（解析后预览并确认）、下载示例表格、导出名单到本机；无法上传时可粘贴表格内容 |
| `pages/admin/settings` | 登记模式（审批 / 直接登记）、二维码规则说明，并跳转到「登记管理」 |
| `pages/admin/register` | **登记管理**：登记开关、登记开放时间、工位使用期限（默认）与**登记批次**（不同批次登记的同学可使用不同期限）、重置演示数据 |
| `pages/admin/qrcode` | 卡片式工位标签导出：顶部主题色标题条 + 白底二维码 + 工位编号 + 楼栋名称 + 序号提示（①②③）+ 底部色条；可改标题/提示/底部文案，可调配色、码点形状、纠错等级、每行个数、中心徽标；一键分页导出（3 倍分辨率）到相册、复制内容清单 |

审批页支持「一键通过」批量审批，已被他人登记的工位自动跳过。

| 页面 | 管理员在工位地图的操作 |
| --- | --- |
| `pages/seat` | 地图格子显示**数字编号**（如 0102），点击弹出详情：所属区域、工位编号、使用人、位置（二维码编号与配套信息不在地图详情展示）；管理员可修改工位编号（弹窗输入、校验重名与空值）、标记/恢复维修、释放归属 |

### 工位标签样式（`utils/qr.js`）

参照工位标签实物绘制，每张卡片自上而下：

```
┌────────────────────┐
│ 主题色标题条（系统名） │  headerText / headerColor
│  ┌──────────────┐  │
│  │    二维码      │  │  QR_BASE/s/{二维码编号}，白底静默区
│  └──────────────┘  │
│   工位编号            │  showCode
│   科研主楼 3F         │  showZone（办公室配置中的「楼栋」）
│  ① 提示一           │  tips[]，numbered 控制是否画序号圆点
│  ② 提示二           │
│  ③ 提示三           │
│ 主题色底条 · 单位     │  footerText
└────────────────────┘
```

- 文案均可编辑（留空即隐藏该区域）；**标题字号自适应**：优先排一行（放不下则自动缩小，不低到影响可读），仍放不下时折成两行并加高标题条，极端超长才截断；工位编号与楼栋名称各占固定行高，均完整显示不重叠。
- **楼栋名称**：取办公室配置中的「楼栋」字段（如「科研主楼 3F」），楼栋留空时回退办公室名称，再为空则显示「X 区」；管理员改楼栋后标签同步更新。
- 每张卡片固定 210 逻辑像素宽，画布宽度 = 列数 × 210 + 间隔；手机端预览可左右滑动，导出按 3 倍分辨率（3 列时约 2058px 宽），适合直接打印裁剪。
- 主题（科技蓝/经典黑/墨绿/深灰）会同时切换标题条与底条颜色；另可调码点形状（方形/圆点）、纠错等级（L/M/Q/H）、中心徽标。

## 五、Excel 批量导入学生

- **上传即导入**：`pages/admin/students` 点击「上传 Excel 文件」→ `wx.chooseMessageFile` 选择本机/聊天中的 `.xlsx`、`.csv`、`.txt` 文件 → 解析为表格 → **导入预览**（总行数、有效条数、新增/更新条数、无效行数，含前 8 条明细）→ 点击「确认导入」写入。
- **示例表格**：「下载示例表格」生成含 2 条示例数据的 CSV（带 BOM，Excel 打开不乱码）并保存到本地设备。电脑端微信通过 `wx.saveFileToDisk` 直接另存，移动端通过预览/转发保存；失败时给出示例内容并可复制。
- **导出名单**：「导出名单到设备」将当前学生名单写成 CSV 保存到本机（手机端可转发到文件传输助手后保存），也可「复制名单」粘贴到 Excel。
- **表头识别**：首行含「学号/姓名/学院/年级/导师/手机/邮箱」等关键字即按列名映射，否则按列顺序取值；学号已存在则更新，缺少学号或姓名的行在预览中标记为无效行并跳过。
- 解析实现：`utils/excel.js`（CSV 自动识别逗号/制表符/分号与引号；xlsx 通过 `utils/inflate.js` 解压 zip，解析 `sharedStrings.xml` 与 `sheet1.xml`），字段映射在 `store.parseStudentRows()`。

## 六、宽屏 UI：电脑端（Windows / Mac 微信）与平板

电脑 / 平板横屏登录时不再显示拉伸后的移动端版面，而是启用一套独立的**桌面工作站 UI**（`components/pc-shell`）。

### 启用范围（重要）

**默认规则：管理员在电脑端登录后直接就是电脑版（后台控制台）**；手机上（以及学生 / 未登录）永远是手机版。管理员可以手动切回「手机版页面」，选择记在缓存 `ui_pc_mode`，之后就按选择来。

| 状态 | 说明 |
| --- | --- |
| 管理员 + 电脑端 + 没选过版本 | **电脑版**（`wideUI()` 里按 `deviceIsDesktop()` 兜底） |
| 管理员选「电脑版 / 手机版页面」 | 当前页立即切换，之后所有页面都按该选择渲染；选择记在 `ui_pc_mode` |
| 管理员 + 手机 | 手机版（手机上不启用电脑版骨架） |
| 学生 / 未登录 | 不显示任何切换入口，永远手机版 |

- **切换入口（首页）**：管理员登录后，首页顶部蓝色用户卡片**右上角**的「手机版 / 电脑版 ▾」下拉按钮，展开后选择「手机版页面 / 电脑版页面」。
- **切换入口（电脑版）**：电脑版顶栏右上角有「手机版」按钮，点击即时切回手机版。
- 实现方式：切换时写偏好 → `layout.syncPageFlags()` 同步宿主页面 `isWide/isPC/uiMode` → `layout.emitLayoutChange()` 通知已挂载的 `pc-shell` 重算 → 刷新页面数据；全程不跳转，也不再依据手机 / 电脑设备判定。

> **排查「管理员登录后显示的还是学生页面」**（三个历史原因，均已修）：
> 1. **页面数据停在初始值**：`layout.wrap()` 注入的 `apply()` 一旦抛异常，会中断页面 `onShow`，`data.user` 停在默认的 `{}`、`isAdmin` 停在 `false`，于是渲染出「空名字 + 研究生标签 + 我的工位」的学生骨架（底部导航却读全局，仍是管理员的审批 / 后台）。现已 try/catch 包裹，布局异常不会再阻断页面生命周期。
> 2. **用户对象是脏数据**：缓存 `gss_current_user` 里若是 `{}` 或只有 `id`（早期版本 / 热重载写入），`user.role` 就不是 `admin`。`store.getCurrentUser()` 现在会校验并自愈（按 id 反查管理员 / 学生档案补全字段，写回缓存），连 `id`/`name` 都没有则返回 `null`（回登录页）。
> 3. **登录页身份选错**：以前选了「学生」再输管理员账号会被拦下（只弹一个 toast），页面仍停在上一个会话。现在账号 + 密码正确就按账号真实身份登录，`role` 仅作提示。
>
> 另外统一了取值入口 `app.getUser()`：以缓存为准并回写 `globalData.userInfo / isAdmin`，页面与底部导航不会再出现角色不一致。

### 设备判定（`utils/layout.js`）

| 判定 | 条件 | 用途 |
| --- | --- | --- |
| 电脑端 `pc` | 微信 Windows / Mac（开发者工具宽度 ≥ 1024 也可识别） | 计算电脑版画布参考尺寸 |
| 平板端 `pad` | iPad / 平板（型号含 pad/tablet/SM-T 或设备短边 ≥ 600px）**且横屏** | 同上 |
| 手机端 `phone` | 其余（含平板竖屏、手机横屏） | 同上 |

> 注意：设备判定**只用于计算画布尺寸，不再决定是否启用电脑版**。是否进入电脑版完全由管理员的版本选择决定（默认手机版）；在手机上选了电脑版时，也会按 `pc` 模式重新计算画布（铺满当前窗口，见下）。

- 判定结果写入 `globalData.layout`；`layout.wrap()` 为每个页面注入的是**当前页实际渲染哪一版**的结果：`isWide` / `isPC` / `isPad` / `uiMode`（非后台页或非管理员时均为手机版取值）；监听窗口尺寸变化实时重算，拉伸窗口即时重排。
- 统一判定入口：`layout.pcAllowed()`（当前用户是否管理员）与 `layout.wideUI()`（再叠加版本选择）。
- **底部导航栏是页面内组件 `components/tab-nav`**：`app.json` 已不再配置 `tabBar`（WeChat 的 tabBar 容器无法可靠收起，会在电脑版底部留下白条），导航由 `pc-shell` 只在**手机版分支**渲染，电脑版根本不会渲染它。
- 手机版页面**不再有任何额外的切换条**：后台页面在手机版下与普通页面完全一致，切回电脑版请用首页右上角下拉菜单。
- `layout.activeLayout()` 返回当前实际生效的画布尺寸：手机上也选了电脑版时，会按 pc 模式重算画布，避免用手机的空画布去渲染电脑版骨架。
- 调试开关 `utils/layout.js` 顶部 `DEBUG_FORCE_MODE`（默认 `''`，即不生效；填 `'pc'` / `'pad'` / `'phone'` 可在开发者工具里强制预览，顶栏会显示「（调试强制）」标识）。

### 全屏工作站画布

- 画布**直接铺满整个窗口**（100vw × 100vh，无外边距、无圆角投影）：顶栏 + 导航 + 内容列刚好占满，微信电脑端把小程序窗口最大化即得到「全屏」的桌面应用效果，拖拽改变窗口大小后立即重算（`app.js` 的 `wx.onWindowResize` → `layout.emitLayoutChange()`）。
- 尺寸分配：`内容列宽 = 窗口宽 − 侧栏 − 间距 × 2`、`内容列高 = 窗口高 − 顶栏 − 间距 × 2`，宽高两个方向都没有空带。
- 画布 chrome 用 px 排版并保持清晰：侧栏 208px（画布 < 900px 自动收成 72px 图标条，< 560px 再收成 56px）、顶栏 56px、间距 16px（窄屏 8px）。
- **窗口能不能放大/全屏，取决于 `app.json` 的 `resizable`（小程序限制，不是页面样式）**：

| `app.json` | PC 微信里的表现 |
| --- | --- |
| 不配置（默认） | 窗口锁死在手机比例，拖拽只能微调、**无法全屏** |
| `"resizable": true` | 窗口可自由拖拽改变大小，鼠标移到边缘出现调节图标，**可最大化到全屏** |

  本项目已在 `app.json` 开启 `"resizable": true`。验证时注意：**开发者工具模拟器里看不出效果**，要用「预览 → 自动预览 → 启动 PC 自动预览」在微信 PC 客户端里打开，或直接真机 PC 体验版。窗口尺寸变化由 `app.js` 的 `wx.onWindowResize` 捕获并 `layout.emitLayoutChange()` 即时重排。
- **内容列铺满画布可用宽度**，移动端 rpx 排版按固定比例缩放后放入：1rpx ≈ 0.58 视觉像素（`RPX_PX`，见 `utils/layout.js`），所以 32rpx 标题 ≈ 18.6px、26rpx 正文 ≈ 15.1px，**窗口再宽字号也不变**，内容真正左右铺开而不是被整体放大。
- 缩放后滚动区域由 `pc-shell.syncScalerHeight()` 按视觉高度修正（`scaler` 写高度、`pc-layer` 绝对定位），避免 transform 缩放导致「能滚出一大段空白」；测量失败时退回 `flowing`（内容按原始高度参与布局，不会被裁掉）。
- 页面在内容列内部滚动（`pc-shell` 接管滚动，交由顶栏「刷新」按钮替代下拉刷新）。

## 七、登记开放时间与批次（自动开闭）

- **设置项**（`pages/admin/register`）：是否开放登记（开关）、登记开放时间（起止日期，留空表示不限）、工位使用期限（默认起止）、**登记批次**（批次名 + 该批次的登记时间窗口 + 该批次的使用期限）。
- **自动开闭**：每次登记/申请按当天日期实时判定，无需管理员手动操作：
  - 手动关闭 → 立即停止；
  - 今天 < 开始日期 → 未开放（提示「登记将于 X 开放」）；
  - 今天 > 结束日期 → 已关闭（提示「登记已于 X 结束」）；
  - 今天落在某个批次的登记窗口内 → 该批次开放，且**该批次的登记使用批次自己的使用期限**。
- **期限分配**：命中批次用批次期限，未命中用默认期限；申请单会记录 `batchName`，便于区分不同批次的同学。
- **生效范围**：学生的扫码直接登记（`claimSeat`）与提交申请（`createApp`）都会被拦截并返回 `REGISTER_CLOSED`；管理员审批、停用/恢复、释放归属不受影响。
- **一工位一归属**：学生名下已有工位时，再登记/申请其他工位会在**学生端驳回**（提示已登记工位编号），数据层同样拒绝（`ALREADY_HAS_SEAT`）；需先在原工位退订。扫码查看自己的工位不受影响。
- 实现位置：`store.registerState()` / `store.currentTerm()`（本地模拟）与 `server/index.js` 同名函数；接口 `GET/POST /api/settings` 会返回 `register`（开放状态）与 `term`（当前期限）。

## 十、部署到微信云托管（不依赖本地电脑）

> 关键点：云托管是**随时可能重启 / 扩缩容的容器**，容器内的**文件系统不保证持久化**。
> 直接沿用 `server/data/state.json` + `server/data/uploads`，重启后办公室、工位、地图照片全丢。
> 所以服务端抽出了存储层 `server/storage.js`，两套实现：

| 模式 | 触发条件 | 状态存在哪 | 照片存在哪 | 适用 |
| --- | --- | --- | --- | --- |
| `file` | 不配 `DB_HOST`（默认） | `server/data/state.json` | `server/data/uploads/` | 本机开发，零依赖 |
| `mysql` | 配了 `DB_HOST` | 数据库 `app_state` 表（JSON） | 数据库 `map_image` 表（LONGBLOB） | 云托管部署 |

### 环境变量（`server/.env.example`，填到控制台「服务 → 环境变量」）

| 变量 | 说明 |
| --- | --- |
| `STORAGE` | `mysql` / `file`，不填时按有没有 `DB_HOST` 自动判断 |
| `DB_HOST` `DB_PORT` `DB_USER` `DB_PASSWORD` `DB_NAME` | 云数据库 MySQL 连接信息（用内网地址） |
| `DB_SSL` | 需要 SSL 时设为 `true` |
| `QR_BASE` | 二维码里固定的域名 |
| `PORT` | 云托管默认 80 |

启动流程（已在 `server/index.js` 的 `bootstrap()` 里）：`storage.init()` → `storage.load()`（没有则播种演示数据并落库）→ 才 `listen`，**避免请求先进来时数据还没准备好**。收到 `SIGTERM` 时会再刷一次状态。

### 构建与部署

```bash
# 构建镜像（Dockerfile 只拷服务端源码，不带本地 data）
docker build -f server/Dockerfile -t gss-seat-server .

# 本地验证（file 模式即可；用 mysql 模式加 --env-file server/.env.example）
docker run -p 8080:80 gss-seat-server
```

微信云托管控制台：新建环境 → 服务 → 新建服务（上传 Git 仓库或本地代码，选 `server/Dockerfile`）→ 配置环境变量与 MySQL 内网地址 → 发布。

### 小程序端切换云托管调用

`utils/config.js`：

```js
CLOUD_RUN: true,
CLOUD_ENV: '<云托管环境ID>',      // 控制台 Environment 页面复制
CLOUD_SERVICE: 'gss-seat',       // 服务名
CLOUD_PUBLIC_BASE: 'https://<服务的公网域名>',  // 「服务 → 公网访问」开启后复制
```

- `CLOUD_RUN = true` 时接口走 `wx.cloud.callContainer`（`utils/api.js` 的 `cloudRunHttp`），**走微信内网，不需要配置 request 合法域名**；
- `app.js` 的 `initCloud()` 会在 `CLOUD_ENV` 非空时调用 `wx.cloud.init()`；
- **地图照片例外**：`<image src>` 拉不了 callContainer，所以照片仍走公网域名（`config.assetBase()` 会在云托管模式下用 `CLOUD_PUBLIC_BASE`），这个域名需要加到小程序后台的 downloadFile 合法域名里；
- **上传照片的坑（已处理）**：`callContainer` 对请求体大小敏感，手机原图转 base64 很容易超限导致「选完图片就没反应」。
  现在上传前会按 `70 → 50 → 35 → 20` 逐级压缩，直到 base64 ≤ 420KB；仍失败则自动改用 `wx.request` 直连 `CLOUD_PUBLIC_BASE/api/upload`（所以要**同时把公网域名加到 request 合法域名**，与 downloadFile 同一个域名）；两者都失败才回退「只保存本机」，并在提示里带上真实原因。
- 不填 `CLOUD_ENV` 时一切照旧走 `BASE_URL`。

### 费用口径（云托管）

按这几个维度计费，**具体的免费额度以控制台「费用中心 → 免费额度」为准**（会随官方活动调整）：

| 计费项 | 说明 | 本项目可控手段 |
| --- | --- | --- |
| 容器资源 | 按实际运行的 CPU / 内存（GB·秒）计费；**没有请求可以缩容到 0**，空闲不计费 | 实例数设最小、开启「缩容到 0」（代价是冷启动 1~2 秒） |
| 公网出流量 | 入流量免费，出流量（返回给小程序的数据、地图照片）计费 | 照片走 CDN 缓存（`GET /uploads` 已带 `cache-control`）、调用走内网 |
| 云数据库 MySQL | 按实例规格 + 存储 + 备份计费，**通常唯一的固定月支出** | 选最低配即可（本项目数据量很小） |
| 云存储 / COS | 若后续把照片改存对象存储，按容量 + 下行流量 + 请求次数计费 | 当前方案把照片放在 MySQL，暂不产生这项 |

> 一句话：在校内工位管理这种低流量场景，容器基本在免费/几分钱级，主要月支出是云数据库最低配的实例费。

### 云数据库的几个「改不了」的地方（踩过）

| 项目 | 事实 | 应对 |
| --- | --- | --- |
| MySQL 版本 / 字符集 / 存储上限 | 创建时确定，**实例详情页不可改**，只能「重启」 | 不用改：建库时显式 `CREATE DATABASE seat CHARACTER SET utf8mb4 COLLATE utf8mb4_general_ci;`；建表 DDL 里每张表都写了 `DEFAULT CHARSET=utf8mb4` |
| 算力 `0.25 - 16` | 是 Serverless 的**弹性范围**（按 CCU 自动伸缩），不是一个待填的规格 | 无需处理；低流量基本停在最低档 |
| 自动暂停 10 min | 创建时可设（部分实例创建后不可改）。暂停后旧连接全部失效，**第一次请求会 500 或慢几秒** | `server/storage.js` 已做「连接类错误 → 重建连接池 → 重试一次」，并把 `connectTimeout` 放宽到 15s；能关掉更好 |
| MySQL 5.7 | 我们的 DDL / `ON DUPLICATE KEY UPDATE ... VALUES()` 都是 5.7 语法；`map_image.name VARCHAR(191)` 主键 = 764 字节 < 767 | 无需升级到 8.0 |

> 若真需要换版本或换字符集，只能**新建一个 MySQL 实例**，再改云托管服务的 `DB_HOST` 并重新发布——不能原地改。
>
> 另：单张地图照片超过 4MB 时可能撞上 MySQL 的 `max_allowed_packet`，报 `Packet too large`；客户端已压缩（quality 70），如仍遇到就把服务端 `UPLOAD_MAX` 调到 3MB。

### 云数据库后台怎么操作（控制台 + SQL）

| 要做的事 | 去哪 | 说明 |
| --- | --- | --- |
| 新建业务库 | 数据库管理 → 顶部「新建」→ 数据库 | 名字 `seat`，字符集选 **utf8mb4**。**不建库服务起不来**（报 `ER_BAD_DB_ERROR: Unknown database 'seat'`）。也可以直接复用模板自带的 `nodejs_demo` 库（把 `DB_NAME` 填成它），省一步，但两处要一致 |
| 执行 SQL | 顶部「SQL 窗口」 | 建表**不要手动做**，服务首次启动会自动建 `app_state` / `map_image` |
| 拿连接信息 | 实例详情「连接信息」/ 「库管理」 | 内网地址 + 端口 + 账号；密码在「账号管理」里重置 |
| 备份 / 迁移 | 顶部「导入导出」 | 改数据前先导出；迁到新实例也用它 |
| 看库里有什么 | SQL 窗口 | 见下方校验语句 |

```sql
-- 1) 建库（只需一次；已建过可跳过）
CREATE DATABASE IF NOT EXISTS seat CHARACTER SET utf8mb4 COLLATE utf8mb4_general_ci;

-- 2) 服务首次启动后检查（应有两张表，且 app_state 只有一行 id='default'）
USE seat;
SHOW TABLES;
SELECT id, CHAR_LENGTH(data) AS bytes, updated_at FROM app_state;
SELECT name, size, created_at FROM map_image;

-- 3) 换设备 / 换库前做备份
--    控制台「导入导出」导出 seat 即可；业务数据就是 app_state 里的那一行 JSON
```

> `app_state` 只维护一行（`id='default'`），整份业务数据是这行里的 JSON。**不要用 `DELETE` 清它**——服务会当成首次启动，重新播种演示数据（原有的办公室/工位/归属全没）。
>
> 控制台里的 `Counters` 目录是系统表，忽略即可；左侧出现的 `nodjes_db` 是模板自带的库，我们不用它。
